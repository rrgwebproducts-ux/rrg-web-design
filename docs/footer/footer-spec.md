# Footer Rebuild — Engineering Spec

Project: a production-intent global footer for Roof Racks Galore, added to all 5 PDP prototype templates (none of which currently have a footer at all).

Companion project to `spec.md` (the PDP template rebuild) and `header-spec.md` (the global header rebuild) — same repo, same conventions (plain HTML/CSS/JS prototypes, `prototypes/_shared/` shared component library, Playwright verification before calling anything done, no push to git until Brenton's explicit sign-off, a developer-brief handover doc gated on its own separate sign-off). This file is the engineering spec/build log for the footer specifically; it does not duplicate `spec.md`'s or `header-spec.md`'s content.

## 0. Goal & scope

Design source: `Footer Design/Footer Component - Desktop.png` and `Footer Component - Mobile.png` (Figma exports, added to the project root 2026-09-14). Unlike the header project, there is no existing placeholder to replace — none of the 5 templates currently render a footer at all, so this is greenfield.

**Scope decisions locked in via `AskUserQuestion` on 2026-09-14 (settled, not to be re-litigated):**
1. **Build order:** build directly into all 5 PDP templates in one pass — no isolated `prototypes/footer/` prototype first (unlike the header). Rationale: the footer is static content with no interactive states worth reviewing in isolation (no drawers, hover cascades, or mobile takeover to prototype).
2. **Link destinations:** every footer link (About Us, Terms and Conditions, Warranty, etc.) is a placeholder (`href="#"`) for now, same convention as the header's Store Finder/Fit My Vehicle/Catalogue/Services links — real URLs to be supplied by Brenton later.
3. **Region variance is in scope now** (not deferred like the header's UK variant was). See Section 3.

**In scope:** the footer block itself (four-column desktop layout collapsing to stacked sections on mobile, per the Figma), added identically to all 5 templates below the existing page content; region-aware behaviour reusing the header/PDP project's existing region system (`applyRegion()` in `shared.js`) rather than inventing a parallel one; a new `FOOTER-DEVELOPER-BRIEF.md` once stable, gated on Brenton's separate sign-off, same as the PDP and header briefs.

**Out of scope:** any change to page content above the footer; real backend behaviour for the newsletter/contact links (visual-only, matching the rest of this project's prototype-not-production convention); sourcing official brand-kit assets for social/payment icons (Section 4 — built as placeholders, flagged as a data gap).

## 1. Design source — what the Figma shows

**Desktop** (`Footer Component - Desktop.png`, 2880×798 reference canvas): dark background (`#211E20`), four columns left-to-right:
1. **Information** — heading + link list: About Us, Opening Hours, Wholesale Policy, Privacy Policy, Careers, Feedback, Contact Us, Checkout Error Form.
2. **Customer Service** — heading + link list: Terms and Conditions, Warranty, Payment and Pricing, Shipping & Delivery, Refund & Exchange, Frequently Asked Questions.
3. **Store Finder** + **Online Orders and Enquiries** stacked in one column:
   - Store Finder: yellow pin icon + "Click here to find your closest store from our 35 nationwide locations." ("Click here" underlined, links out).
   - Online Orders and Enquiries: support-hours paragraph ("Our team is here to support you. Phone and chat is open Monday to Friday, 8:30am to 5pm AEST (closed Public Hols)."), an info-icon email row (`help@roofracksgalore.com.au`), a phone-icon "Call Us 1300 071 264" row.
4. **Brand column** (right-aligned): full Roof Racks Galore logo (white/red, stacked lockup — larger than the header's horizontal lockup), "Follow Us" heading + 4 circular white social icon buttons (YouTube, Facebook, Instagram, TikTok), "Payment Options" heading + payment-method icon row (PayPal, Visa, MasterCard, Zip, Afterpay, Apple Pay, Google Pay).

Below the four columns: a full-width light bar (`#F5F5F5`) with centered copyright text, "© 2026 Roof Racks Galore".

**Mobile** (`Footer Component - Mobile.png`, 780×2154 reference canvas): everything stacks to one column, in this order: Information list, Customer Service list, Store Finder, Online Orders and Enquiries, Follow Us + social icons (centered), Payment Options + payment icons (centered, wraps to 2 rows), brand logo (centered), copyright bar. Two-column Information/Customer Service pairing (side by side) is kept even on mobile per the Figma — only the columns below them go full-width/centered.

Typography/colour matches the rest of the site's existing convention already in `shared.css`: column headings are uppercase Barlow Condensed bold (same treatment as e.g. the header's nav labels), body/link text is Lato, heading/link text is white on the dark background, the copyright bar uses dark text on its light background.

## 3. Region variance — locked in via `AskUserQuestion` on 2026-09-14

Confirmed scope: brand identity, copyright text, phone number, Store Finder copy, and payment badges vary by region. Everything else (link labels, layout, socials) is identical across AU/NZ/UK.

1. **Brand/logo:** UK trades as a real sister brand, "The Roof Box Company" (`roofbox.co.uk`) — already has its own logo asset (`prototypes/_shared/brand-roofbox-uk-logo.svg`, a self-contained yellow/navy badge, usable as-is on any background) and is already swapped into every `.rrg-logo img` on the page by the existing `applyRegionBrand()` function. The footer's brand-column logo just needs the `rrg-logo` class/structure so it picks up this swap for free — no new region-branching code needed for the swap itself.
   - **New asset added this session:** `prototypes/_shared/headerlogo-white.png` — a white-text/red-accent recolour of `headerlogo.png` (which is black-text-on-transparent, built for the white header, and unreadable on the footer's dark background). Generated programmatically (pixel recolour preserving the red accent and alpha channel exactly, no other differences) since no white variant existed. Used as the footer's AU/NZ logo; UK continues to use the existing self-contained `brand-roofbox-uk-logo.svg` unchanged.
2. **Copyright text:** "© 2026 Roof Racks Galore" (AU/NZ) vs "© 2026 The Roof Box Company" (UK) — new region-driven text swap, same pattern as the existing trust-row copy swaps in `applyRegion()`.
3. **Phone number:** reuses `REGION_PHONE` as-is (AU 1300 071 264 / NZ 09 481 1910 / UK 01204 899778) — the footer's "Call Us" row gets the same `data-trust`-style treatment already used for the header/trust-row phone number.
4. **Store Finder copy:** "35 nationwide locations" (AU) vs single-store wording for NZ/UK, reusing `REGION_SINGLE_STORES` — same convention as the existing Nearest Store / Showroom Finder region text.
5. **Payment Options row:** reuses `paymentBadgeSet(currentRegion)` — AU: PayPal + Visa/MasterCard + Zip + Afterpay + Apple Pay + Google Pay; NZ: same minus Zip; UK: PayPal + Visa/MasterCard + Clearpay + Klarna (drops Afterpay/Zip, per the existing UK payment-provider set) + Apple Pay + Google Pay. Card network icons (Visa/MasterCard/Apple Pay/Google Pay) are not region-specific themselves — only which BNPL providers appear changes.

**Expanded 2026-09-14 (design-review round 2) — UK now diverges much further, matching the real roofbox.co.uk footer rather than just reskinning the AU layout:**

6. **Footer background colour:** UK is blue (`#2E41AE` — reused directly from the existing `body.region-uk{--rrg-red:#2E41AE}` brand token in `shared.css`, not a new colour value) instead of AU/NZ's near-black `#211E20`. Applies to the whole footer block *and* the bottom bar — on the live site it's one continuous blue field, no separate light bar, so `.footer-bottom` gets the same override rather than staying light-grey for UK.
7. **"#TakeMoreDoMore" tagline:** UK-only, shown in the brand column between the logo and Follow Us. Real TRBC brand copy, set in **Kalam** — confirmed via the live site's own computed styles (`font-family:'kalam, arial, helvetica'`, `font-weight:700`), not guessed — added to each template's Google Fonts `<link>`. Hidden (`hidden` attribute, toggled by `applyRegionFooter()`) for AU/NZ, which have no equivalent tagline.
8. **Follow Us social icons — now genuinely region-specific, not just reskinned:** AU/NZ have no real social accounts yet (Section 4 below), so they keep the existing generic glyphs in solid white circle buttons. UK has real accounts and real icon assets, fetched live from roofbox.co.uk 2026-09-14 (not recreated/traced) — Facebook/YouTube/Twitter/Instagram (a different platform set than AU's YouTube/Facebook/Instagram/TikTok — no TikTok), each linking to TRBC's real profile, rendered via the live site's own thin-white-ring-outline icon style (baked into the SVG geometry itself, so the button wrapper stays transparent rather than adding a second circle). Driven by `renderFooterSocial(region)` + `REGION_FOOTER_SOCIAL` in `shared.js`, same data-driven pattern as the payment icons.
9. **Copyright bar content — UK shows real company/legal text, not a copyright line:** "© The Roof Box Company (TRBC) Ltd, Unit 4 Station Yard, Station Road, Sedbergh, Cumbria, LA10 5HP" + "Registered in England No. 16901742    VAT No. 512 2969 95" (two lines), replacing AU/NZ's plain "© 2026 Roof Racks Galore". This is real text supplied by Brenton, not a placeholder like the NZ/UK emails in Section 4.

**Not varied:** Information/Customer Service link lists, section headings, overall column layout/structure.

## 4. Data gaps — flagged, built as placeholders per this project's existing convention

Same convention as the header's missing category icons (`header-spec.md` Section 3.6) — build the slot now with a reasonable placeholder, flag it here rather than blocking on real assets.

1. **Social icons — AU/NZ only** (YouTube, Facebook, Instagram, TikTok): no real RRG social accounts/assets exist anywhere in this project. Built as simple inline-SVG glyphs (generic recognisable marks, not traced from any official brand-kit file) in white circles, matching the Figma's circular-button treatment. **Should be swapped for real accounts + official brand-kit assets before this leaves prototype stage.** UK is **not** a gap any more — real TRBC accounts and real icon assets, see Section 3 item 8.
2. **Payment icons — Visa, MasterCard, Apple Pay, Google Pay, plus dark-background versions of Zip/Afterpay/Clearpay/Klarna:** **resolved 2026-09-14** (see Section 3 item 5 and the Build Status Log) — real CC0-licensed monochrome marks sourced from Simple Icons for the first five, and hand-recoloured (white/purple) variants of this project's own existing Zip/Clearpay assets for the other two. Not hand-drawn placeholders any more, but also not each brand's own official press-kit asset — **still worth swapping for official brand-kit "on dark" logos before this leaves prototype stage**, just a much smaller gap than before.
3. **NZ/UK support email:** the Figma only shows the AU address (`help@roofracksgalore.com.au`); no NZ/UK equivalent exists anywhere in this codebase. Defaulted to the equivalent domain per region (`help@roofracksgalore.co.nz`, `help@roofbox.co.uk`) as a placeholder. **Needs Brenton to confirm the real addresses.**

## 5. Where it lives

- Markup: a new `<footer class="rrg-footer">` block added identically to all 5 templates (`prototypes/{simple,config-variant,sibling-color,vehicle-specific,grouped-bundle}/index.html`), placed as the last element before `</body>` (after any existing sticky/mobile-only elements, same convention as the header's mobile takeover placement).
- Styling: new `prototypes/_shared/footer.css`, linked from each template's `<head>` alongside the existing shared stylesheets.
- Behaviour: region-driven text/asset swaps added as new branches inside the existing `applyRegion()` in `shared.js` (not a separate footer.js) — since the swaps are simple text/attribute updates reusing data already loaded for the header/trust-row, not a self-contained interactive component like the mega menu.
- New assets: `prototypes/_shared/headerlogo-white.png` (Section 3), plus the placeholder social/payment icons (Section 4) — added inline as SVG in `footer.css`/markup rather than as separate image files, since they're simple enough not to need it and this keeps them trivially recolourable later without regenerating image assets.

## 6. Build Status Log — read this first if picking up in a new session

**2026-09-14:** Spec written, scope locked in via three `AskUserQuestion` rounds with Brenton (build order, link URLs, region variance — Sections 0 and 3 above). Build not yet started as of this entry.

**2026-09-14 (same day, build complete):** Footer built directly into all 5 PDP templates in one pass, per Section 0's build-order decision — `footer.css` added, markup inserted identically before each template's closing scripts, region logic (`applyRegionFooter()`, `REGION_FOOTER_BRAND`/`REGION_FOOTER_EMAIL`/`REGION_FOOTER_BNPL`/`FOOTER_PAYMENT_SVG`/`renderFooterPayments()`) added to `shared.js` and wired into the existing `applyRegion()` sweep.

Two real bugs caught and fixed during Playwright verification, not caught by static review:
1. **Logo went invisible on the dark footer.** The header's existing `applyRegionBrand()` unconditionally sets every `.rrg-logo img` on the page to the black-text AU/NZ logo (built for the white header) — it silently overwrote the footer's own white-logo `src` on page load. Fixed by teaching `applyRegionBrand()` to treat `.rrg-footer .rrg-logo img` as a separate case (footer gets `RRG_LOGO_WHITE`/`UK_LOGO`, header keeps `RRG_LOGO`/`UK_LOGO`) rather than writing a parallel region function that would have fought the existing one. New asset: `prototypes/_shared/headerlogo-white.png`, a pixel-recolour of `headerlogo.png` (black text → white, red accent and alpha untouched) — generated programmatically since no white variant existed and no image-editing tool was available in this environment (verified by direct pixel-count and a manual composite-on-dark-background check before use, not just visual guess).
2. **Payment icon row overflowed/misaligned.** `.footer-payment-icons .payment-icon svg{height:100%}` only ever matched the new inline-SVG placeholders (Visa/MasterCard/Apple Pay/Google Pay) — the real `<img>`-based assets (PayPal/Zip/Afterpay/Clearpay/Klarna) ignored it and rendered at native size, blowing out the row (Zip's SVG in particular rendered enormous). Fixed by adding `img` alongside `svg` in that CSS rule. Separately, the Google Pay placeholder's own viewBox (`0 0 68 16`) was too narrow for its own text content, clipping the final "y" — widened to `0 0 80 16`.

Verified with Playwright on all 5 templates: footer present, zero console errors, region round-trip AU→UK→AU (logo/copyright/phone/store-copy/payment-badges all swap correctly, confirmed via screenshot not just DOM state), mobile 390px (no horizontal overflow, correct stacked order incl. the reversed brand-column order — social/payment/logo instead of desktop's logo/social/payment). Not pushed — gated on Brenton's sign-off, same as the PDP and header briefs.

`FOOTER-DEVELOPER-BRIEF.md` and `footer-dev-brief-viewer.html` created the same session, following `HEADER-DEVELOPER-BRIEF.md`'s conventions exactly (same Name/Location/Purpose structure, same viewer page copied and re-pointed at the new filename). Screenshots in `footer-dev-brief-assets/` (desktop default, mobile default ×2, UK region, one whole-page "location" shot with the footer outlined in red in place of a hand-drawn arrow, given no image-annotation tool was available). All 12 image references in the brief verified to load (`naturalWidth` check), zero broken.

**2026-09-14 (same day, design-review round):** Brenton reviewed the built footer against the browser and gave 3 corrections plus a request to re-verify against the Figma:
1. **Column headings ("INFORMATION", "STORE FINDER", etc.) rendered near-black, not white.** Root cause: `shared.css`'s global `h1,h2,h3,h4{color:var(--rrg-black)}` (line ~39) sets `color` directly on every heading element, which beats simple inheritance from `.rrg-footer{color:#fff}` — CSS only inherits a property when nothing more specific sets it directly, and an element selector matching the heading itself counts as "more specific" than inheriting from an ancestor. Fixed with `.rrg-footer h4{color:#fff}` (class + type selector, higher specificity than the plain `h4` in the global rule) rather than touching the shared global rule, which other pages depend on.
2. **Information/Customer Service should stay 2 columns side-by-side on mobile, not stack to 1** — this was actually already the intent (footer-spec.md Section 1 says so explicitly) and the 900px breakpoint got it right, but a second `@media (max-width:520px){.footer-grid{grid-template-columns:1fr}}` rule (added defensively during the original build without checking it against the Figma) collapsed everything, including these two, to a single column below 520px — exactly the phone-width range that matters most. Deleted that rule entirely; `footer-info-block` and `footer-brand-col` were already forced to `grid-column:1/-1` independent of that breakpoint, so removing it only affects Information/Customer Service, as intended.
3. **Payment icons — remove the white chip background, use marks built for a dark background instead.** Note: the Figma itself actually shows most payment icons (PayPal/Visa/MasterCard/Zip/Afterpay/Apple Pay) on white or light chip backgrounds, only Google Pay bare — so this is Brenton overriding the Figma's own treatment on this one element, not a fidelity bug; matching his explicit ask took priority over pixel-matching the Figma here. Sourced real CC0-licensed monochrome "on dark" marks from Simple Icons (`cdn.simpleicons.org`, requested pre-coloured white) for Visa, MasterCard, PayPal, Apple Pay, Google Pay, and Klarna — downloaded and vendored locally into `payment-logos/` as `*-dark.svg` (not loaded from the CDN at runtime, matching this project's convention of vendoring real assets rather than depending on a live third party). Zip and Clearpay aren't in Simple Icons, so their existing local assets were hand-recoloured instead: Zip's dark wordmark path recoloured white with its purple accent kept as-is (matching Zip's own real "on dark" lockup convention), Clearpay's solid-black wordmark recoloured fully white. `shared.js`'s `FOOTER_PAYMENT_ICON` map and `renderFooterPayments()` simplified to a single image-based path (no more inline-SVG hand-drawn placeholders — that whole `FOOTER_PAYMENT_SVG` block was deleted). CSS chip styling (`background:#fff;border-radius;padding`) removed from `.payment-icon`; icons now sit directly on the footer's dark background.

Re-verified with Playwright against both original Figma exports side-by-side after all 3 fixes: headings white on both desktop and mobile, Information/Customer Service confirmed 2-up at 390px width, payment icons confirmed chip-free and legible in both AU and UK region states (Clearpay/Klarna included), zero console errors, checked on `simple` and `vehicle-specific` (shared CSS/JS means the fix applies identically to all 5 templates, not template-specific markup). Data-gap status downgraded in Section 4 above — no longer hand-drawn placeholders, but still not each brand's own official press-kit asset.

**2026-09-14 (same day, third round) — UK brought in line with the real live site (roofbox.co.uk), not just the Figma:** Brenton flagged that the UK footer "needs some work" and pointed at the live site directly rather than describing changes abstractly. Implementation: `.rrg-footer`/`.footer-bottom` get a `body.region-uk` background override (Section 3 item 6); a new `.footer-tagline` element (hidden by default, unhidden only for UK) added to the brand column's markup in all 5 templates, styled in Kalam (added to each template's Google Fonts link); social icons converted from static per-template markup to a `data-footer-social-icons` container rendered by a new `renderFooterSocial(region)` + `REGION_FOOTER_SOCIAL` map (mirrors the existing payment-icon pattern) — two button styles coexist via `.social-btn-solid` (AU/NZ, white circle + glyph) vs `.social-btn-outline` (UK, transparent, ring baked into the real vendored asset); `REGION_FOOTER_LEGAL` replaces the old `REGION_FOOTER_BRAND`-based copyright swap, rendered via `innerHTML` (not `textContent`) so UK's 2-line block can include a `<br>`.
