# Dynamic fields — Header, PDP, PLP

Every piece of text or media on these pages that comes from data rather than being fixed copy:
where it comes from, the field it reads, and what to show when the value is missing.

- **Generated** from `prototypes/_shared/dynamic-fields.js` by `docs/page-debugger/build-fields-doc.js`, so don't edit this file by hand.
- **See it on the page:** open any template on Vercel with `?debug=1` (or Site Admin → Prototype → Page debugger), tick **Dynamic fields** and hover an outlined field. Tick **Show field names** to see every value replaced by its token ("Shows as" below).
- **Status:** *Draft* means Claude's best guess from the prototype and the developer briefs, not yet checked. *Confirmed* means Brenton has checked it.

- **Product card name** (`plp.cardName`, Magento): sibling-group title sourcing is an open Magento data-model item (brief §6 item 12). Variant cards link to the cheapest sibling.
- **Product ribbon** (`plp.cardRibbon`, Unknown): UNKNOWN: no backend flagging mechanism exists yet (brief §6 item 7). Staff Pick-wins tie-break is an unconfirmed assumption. Never use for stock messages.

- **Related Products strip** (`plp.relatedProducts`, Unknown): UNKNOWN: Magento has no native category-level related products; needs Marc to pick a source (CMS widget, category attribute or recommendations). Static markup in the prototype.

**Notes**

- `global.utility.store`: How the store is first set (shopper picks it, or a geo/IP guess) is not decided yet. The same name also feeds stock lines, Click & Collect and the mini-cart.
- `global.utility.vehicle`: One session vehicle drives the header, PDP fitment card, PLP-family card fitment and search ordering. Mobile drops the "Your Vehicle:" label and shows just the name.
- `global.utility.region`: The prototype reads ?region= or the saved choice; in Magento it is simply which website the shopper is on (the menu links to the other sites).
- `global.header.storeNav`: Flips back automatically when a region opens its second store.
- `global.search.recent`: Only in the empty-box (focus) state. Prototype list is canned, and Clear only hides it for that page view: decide whether Clear should persist.
- `global.search.suggestLinks`: There is no "Algolia" source key yet, so this is filed under Magento. The prototype matches against hardcoded lists in shared.js (RRG_SEARCH_*).
- `global.search.productPrice`: The prototype shows a single price only, with no sale/was price or "From" for products with options. Check that this is what we want.
- `global.menu.l1Icon`: Hardcoded map (MM_CATEGORY_ICONS) in mega-menu.js. Needs an icon field on the category.
- `global.menu.l3`: Every link URL is "#" in the prototype. The crawl captured the labels only.
- `global.footer.storeCopy`: The prototype hardcodes 35 even though it already counts the store list elsewhere (rrgStoreCount). It should be the live count.
- `global.footer.email`: The NZ and UK addresses are still unconfirmed (footer-spec data gap).
- `global.footer.phone`: The same per-region number also fills the PDP Trust Row.
- `global.footer.copyright`: The year is hardcoded in the prototype. It should be the current year.
- `global.footer.social`: AU/NZ hrefs are still "#". The real account URLs are needed.
- `global.footer.payments`: Best guess: this could follow the payment methods enabled in Magento per website rather than a separate list.
- `global.vf.options`: This is the inline widget (Home, FMV, Cart, Brand, VCLP) and the Fit Finder drawer, which reuses the same widget.
- `global.vf.photo`: Where vehicle photos live is unknown: Rackit, a Magento vehicle entity, or a media folder keyed by model? Needs Marc / the Rackit owner.

- `search.card.specs`: This mixes two sources. Specs are probably Magento attributes and USPs are Rackit. Split them if Marc wants one source per entry.

- `search.scopeCard`: The prototype uses hardcoded lists (RRG_SEARCH_PAGES / RRG_SEARCH_BRANDS). These need indexing in Algolia alongside products.

- `plp.breadcrumb`: Last segment is plain text (#plpCrumbLast), the rest are links. Prototype rebuilds it client-side on tab change; production is one URL per tab.
- `plp.breadcrumbVrs`: REVIEW: the brief (4.2, spec.md §15 L8) says year, body and roof type were dropped from the trail on 2026-09-29, but both VPLP prototypes still render them in breadcrumbRoot. Pattern is marked provisional.
- `plp.h1`: Every H1 starts "Shop" (2026-10-02). {vehicle} is the session vehicle label (make + model only, no series/years).
- `plp.h1Vrs`: The VPLP is one vehicle listing, so the suffix is the page vehicle (from the URL / Rackit), not the session vehicle.
- `plp.heroDescription`: Clamped to 3 lines on phones with Read more. REVIEW: the live category description is long SEO copy; this slot probably wants its own short "hero intro" attribute. Same text in both hero states (not vehicle-specific).
- `plp.heroVehicleImage`: Only shown when a vehicle is set. REVIEW: where vehicle cut-out photos live in production (Rackit vehicle record or a Magento media table) is not decided.
- `plp.heroMakeBadge`: Same open question as plp.heroVehicleImage on where make badges are stored.
- `plp.heroCategoryImage`: Prototype uses a real product photo from inside that tab (never the Shop By icon).
- `plp.heroGuideLinks`: REVIEW: prototype links are all "#"; the hide-when-empty rule comes from plp-spec §15 item 5 ("Buyer's Guide/FAQ/Video are dynamic"). Assignment mechanism is an open Graham/Jake item (plp-spec §14 item 1).
- `plp.shopByLabel`: Each tab is its own real URL; filters carry over as URL params so the count matches what you land on. VPLP-accessories shows only tabs this vehicle has products in.
- `plp.shopByIcon`: Real icon set is an open asset task (brief §6 item 8).
- `plp.level3Icon`: REVIEW: on live Bike Racks these icons are attribute-option images, so Level 3 may be an attribute filter rather than a real child category. Needs Marc to confirm.
- `plp.sortOptions`: Option list is one shared list in the prototype (PLP_PRODUCT_SORT_OPTIONS). Best Selling needs sales data, Newest needs a created/new-from date.
- `plp.filterGroupLabel`: Which attributes show, their order and which are priority are set per category/subcategory (brief 4.5) — needs an admin setting. .plp-filter-chip is the mobile priority chip.
- `plp.filterTooltip`: Copy lives in the data-tooltip attribute. Needs a product-accuracy pass by the team (brief §6 item 6).
- `plp.availabilityStore`: Per-store inventory feed does not exist yet (brief §6 item 15).
- `plp.cardImage`: Alt = product name. 4:3 cover crop.
- `plp.cardName`: REVIEW: sibling-group title sourcing is an open Magento data-model item (brief §6 item 12). Variant cards link to the cheapest sibling.
- `plp.cardFitStatus`: Every card on the VPLPs shows it (all products are for the page vehicle). Same component as the PDP fitment card.
- `plp.cardPrice`: Currency follows the region (AU/NZ $, UK £).
- `plp.cardWasPrice`: No "RRP" prefix on cards (spec.md §16 item 21). ACCC flag for Graham: an unlabelled strikethrough reads as our own previous price.
- `plp.cardRibbon`: UNKNOWN: no backend flagging mechanism exists yet (brief §6 item 7). Staff Pick-wins tie-break is an unconfirmed assumption. Never use for stock messages.
- `plp.cardStock`: Wording is shared with the PDP (rrgStockStatus, PDP brief 4.37). Low Stock threshold not defined here.
- `plp.cardStockTip`: UNKNOWN: warehouse name and "also in stock at" stores are demo data until an inventory feed exists. Copy is in the data-stock-tip attribute.
