# Header & Mega Menu Rebuild — Engineering Spec

Project: a production-intent global header and mega menu for Roof Racks Galore, replacing the placeholder header currently embedded in all 5 PDP prototype templates.

Companion project to `spec.md` (the PDP template rebuild) — same repo, same conventions (plain HTML/CSS/JS prototypes, `prototypes/_shared/` shared component library, Playwright verification before calling anything done, no push to git until Brenton's explicit sign-off, a developer-brief handover doc gated on its own separate sign-off). This file is the engineering spec/build log for the header work specifically; it does not duplicate `spec.md`'s PDP content, and `spec.md` does not duplicate this file's header content — cross-reference rather than repeat.

## 0. Goal & scope

**Important correction, 2026-09-13 (read this before Section 3):** the current PDP placeholder header's *shell* — utility bar + single main header row, logo/nav/search/cart — is not a throwaway stand-in. Per Brenton, it's already ~80–90% accurate to the intended final design and **is the structural base to build on**. The live production site's header (the 4-bar red/black/grey/black stack documented in Section 3.1) is the *old* design this project exists to move away from — it is **not** a layout/shell reference, only a content source (Section 3.2's real product-category taxonomy is reused; its bar structure, click-to-open mega-panel styling, and utility-bar item set are not). Don't build toward Section 3.1's stacked-bar structure — build toward the placeholder shell described in Section 1.

The current PDP templates ship with a placeholder header (`.rrg-main-header` / `.rrg-utility-bar`, defined once in each template's markup, styled/scripted from `prototypes/_shared/shared.css`/`shared.js`) built only to make the PDP prototypes navigable during PDP-focused review sessions. Two things in it are genuinely placeholder, not final design: two dev-only tools (the Template Switcher, the Dev Brief link) are mixed directly into the visible nav, and the "Products" hamburger button that currently triggers the Template Switcher needs to trigger a real mega menu instead. Everything else about the shell — the utility bar's content, the single main-header row, the sticky condensed mobile header — is the target design, not a placeholder to be replaced wholesale.

This project's real work is: (a) turn the "Products" nav button into a real mega-menu trigger populated with real product-category content (Section 3.2, reused from the live site), (b) give the 4 plain nav links (Store Finder, Fit My Vehicle, Catalogue, Services) real URLs once Brenton supplies them — they stay as plain links, not dropdowns, (c) separate the genuinely dev-only tooling (Template Switcher, Dev Brief link) out into its own floating admin panel (Section 5) so the shipped-looking header stays honest about what's real.

**In scope:**
1. A new, isolated prototype (`prototypes/header/`) — the placeholder shell (Section 1) with the "Products" button wired to a real mega-menu dropdown (desktop) / accordion (mobile), built independently of the 5 PDP templates first, per Brenton's call on 2026-09-13.
2. A new floating **Admin Panel** (Section 5) — separate from the PDP templates' existing Demo State Panel — housing the Template Switcher, the Dev Brief link(s), and a toggle to show/hide the Demo State Panel FAB, per Brenton's call on 2026-09-13.
3. Once the header prototype and Admin Panel are signed off: integrating them into all 5 PDP templates in place of the current placeholder header/nav wiring (Section 6).
4. Its own developer brief, `HEADER-DEVELOPER-BRIEF.md`, following the same Section 0.1 documentation conventions established in `DEVELOPER-BRIEF.md` (plain-English writing, a screenshot for every visual state, Name/Location/Purpose structure) — built only once the header itself is stable, gated on Brenton's separate sign-off, same as the PDP brief.

**Out of scope:** any change to PDP page content below the header (hero, decision panel, tabs, etc. — that's `spec.md`'s domain); real backend search, cart, or account functionality (visual-only for now, matching this project's existing prototype-not-production convention); real product filtering behind the Fit Finder widget (Section 4, open question); reproducing the live site's own header shell/bar structure (explicitly not the target — see above).

### 3.6 New mega-menu design (Figma, `Mega Menu Designs/`, reviewed 2026-09-13) — this is what actually gets built

Six exports reviewed: `Mega Menu - Final - Level 1/2/3.png` (desktop) and the matching `- Mob.png` variants, plus `Group 33518.png` (a category-header banner asset). This design — not Section 3.1's live-site panel style — is the actual visual/interaction target. Its **content hierarchy deliberately stays as close to the current live-site hierarchy as possible** (Brenton, 2026-09-13: "replicate the current menu in the new design with as little changes to the actual menu hierarchy itself") — only the visual/interaction pattern is new.

**Desktop — one full-width drawer, 3 independent columns (restructured 2026-09-13 — see Section 9's design-review log entry for why):** clicking "Products" opens one edge-to-edge drawer below the main header, height fixed to Level 1's natural content height. Level 1/2/3 are three columns side by side *inside* that one drawer, not per-row flyouts — Level 2 and Level 3's **content** swaps based on which Level 1/Level 2 row is hovered or focused, but the columns themselves always occupy the drawer's full height starting from the top, regardless of which row is hovered. Longer Level 2/3 content scrolls internally within its column rather than growing the drawer.
- **Level 1**: the sidebar column, icon + label + chevron per row. Contains exactly the live site's 8 top-nav items (Section 3.1's category list) — an icon exists per category in the Figma (line-art vehicle/rack icons) that doesn't exist yet in this project's asset set (data gap, see Section 7's Known Data Gaps note once this is added there). A promotional banner (e.g. "Click Here For EOFY Sale + Clearance") sits above the Level 1 list — **treat its copy/link as placeholder/configurable, not fixed content**, same convention as the live site's own "Adventure Sale" banner (Section 3.3). **Brands** (last row) is styled as a distinct full-width yellow "Shop By Brand" bar, matching the Figma, rather than identically to the other 7 rows (confirmed 2026-09-13) — it's still the same data-driven row underneath, just visually set apart.
- **Level 2** (hover/focus a Level 1 category): the middle column, header bar showing the category name (red background, per `Group 33518.png`). Rows are **not** the live site's raw column headings — each of that category's real columns (Section 3.2) becomes a row labelled "Shop " + the column heading verbatim (e.g. Awnings & Roof Top Tents' *Awning Type* column → "Shop Awnings"; its *Brands* column → "Shop by Brand"), plus one **"View All"** row appended per category (links to that category's full listing page — no Level 3 of its own). A merchandising promo tile (product photo + "New Product Release" + name, linked) is pinned to the bottom of the column (scrolls independently of the row list above it) — per-category real content, not yet sourced (Open Question — flagged below as a data gap, build the slot with placeholder content for now, confirmed 2026-09-13).
- **Level 3** (hover/focus a Level 2 row, except "View All"): the right-hand column — that column's real leaf links from Section 3.2, last one bolded ("View All Awnings" style — a category+column listing link). The same promo tile from Level 2 persists, pinned to the bottom of this column too.
- **Brands** follows the identical Level 2/3 pattern using its own already-crawled content (Section 3.2 item 8, confirmed reused 2026-09-13): Level 2 = "Shop by Brand" style entries for its two groupings (Product Brands, Vehicle Makes) + View All; Level 3 = the ~30 brand names / ~70 vehicle makes respectively.
- **Confirmed omitted:** the Figma's "Shop By Vehicle" pinned Level-1 item is **not** being built — it's a new addition not present in the live site's current hierarchy, and Brenton's explicit direction (2026-09-13) is to replicate the current hierarchy with minimal change, not add new nav destinations. Level 1 is the original 8 items only.

**Mobile — full-screen takeover, not a drawer inside the page (rebuilt 2026-09-13 to match this exactly — see the dated build-log entry for how):**
1. Tapping the hamburger opens a full-screen, `position:fixed` takeover, immune to the real page's scroll/sticky-header state — its own mini header (logo, Login/first-name, Select Your Vehicle/vehicle name, a close button) plus a search bar, the promo banner, then the category list (same 8 items, no "Shop By Vehicle", per the desktop note above) with Brands styled the same yellow "Shop By Brand" as desktop. **This is the mobile hierarchy's root — renamed Level 0** (not gated behind a "Products" tap the way it used to be; see the dated log entry for why). The 4 plain nav links (Store Finder etc.) sit below the categories, in their own section.
2. Tapping a category **replaces the screen** with a Level 1 screen: a header bar (category name + back-chevron to Level 0 + a close button), the same "Shop X"/"View All" rows as desktop, the promo tile.
3. Tapping a Level 1 row again **replaces the screen** with Level 2: header bar keeps the category name + back-chevron + close, a secondary row shows the current Level 1 label with a dropdown chevron (likely a same-level jump menu between sibling Level 1 items without going back a full step — confirm at build time, still open, Section 9 punch list item 4), then the real leaf links, promo tile retained.

**Session state (logged in / vehicle set / nearest store set), new 2026-09-13:** the mini header's Login/Vehicle display — and the existing desktop utility bar's equivalent items — are driven by 3 independent admin-toggleable booleans (`prototypes/_shared/session-state.js`), not hardcoded always-on content. ## 5. New Admin Panel — design

Per Brenton's 2026-09-13 decision: **a new, separate floating panel**, distinct from the PDP templates' existing Demo State Panel (`admin-fab`/`admin-panel` in `shared.js`) — not a merge of the two.

- **Own FAB**, visually distinct from the Demo State Panel's FAB (different icon/label, e.g. "Site Admin" vs. "Demo State") so the two are never confused when both are present on a page.
- **Contents:**
  - Template Switcher — moved here from the current main nav (Section 1), unchanged in behaviour (still switches between the 5 PDP prototype templates).
